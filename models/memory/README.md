# Memory — tiny RNN and LSTM weights

Weights for Lab 6. Both cells are trained here, from scratch, by `train.py`. Nothing is downloaded.

## Task

Read a string of `(`, `)` and `.` one character at a time. After each character, say how deep the brackets are nested right now: depth 0 to 4. `.` stands for any other character and leaves the depth alone, so typed text like `f(a(b))` works too.

The answer at each step depends on everything before it. The network can only get it right by carrying a count forward in its hidden state, and that count is what the lab shows.

Training strings are random walks that never go below depth 0 or above depth 4. Outside that range the cells were never trained, and the lab should say so rather than trust the prediction.

## Models

Both use one-hot inputs over `["(", ")", "."]`, a hidden size of 8 and a linear read-out to 5 classes with softmax.

- Elman RNN: `h = tanh(Wxh x + Whh h₋₁ + bh)`, `y = Why h + by`.
- LSTM: gates `i, f, g, o` stacked in that order in `W`, `U`, `b`; `c = f ⊙ c₋₁ + i ⊙ g`, `h = o ⊙ tanh(c)`, `y = Wy h + by`.

Matrices are row-major `[out][in]`. `src/labs/memory/math.ts` runs the same forward pass.

## Training

```
python3 -I models/memory/train.py
```

NumPy only. Seeded, so a rerun writes the same `weights.json`. Adam on mean cross-entropy, length-24 strings, gradient norm clipped to 1. Before training, the script checks backprop against central differences for both cells and stops if they disagree. Weights are rounded to 6 decimals on export, and accuracy is measured after rounding.

## Accuracy

Measured by `train.py`, stored in `weights.json` under `metrics`, and recomputed in TypeScript by `src/labs/memory/math.test.ts` on the same strings (`tests/fixtures/memory.json`).

| Set | Strings | Length | RNN, per character | RNN, whole string | LSTM, per character | LSTM, whole string |
| --- | --- | --- | --- | --- | --- | --- |
| test (seed 12345) | 500 | 24 | 1.0 | 1.0 | 1.0 | 1.0 |
| long (seed 12346) | 200 | 96 | 1.0 | 1.0 | 1.0 | 1.0 |

Neither set is trained on. The long set is four times the training length. The task is easy on purpose: the point of the lab is to watch a correct counter work, not to push a benchmark.

## Why the weights are committed

The project rule is that weights are fetched at runtime and never committed. This file is the exception: it is tiny (the tests keep it under 50 KB), it is generated by the committed script, and the fixture tests need it.
