# Plan — PaperLab v2, "the ladder"

Status: proposed · Owner: Garfield Greg Lim III · Author: Claude (2026-10-15)
Inputs: `docs/VISION.md`, ADRs 0001–0007, `docs/audits/2026-10-15-v1-audit.md`, landscape research (summarised in ADR 0002/0005).

## Goal
Replace the step-through transformer page with ten touchable labs, from a line through points to a real LLM running in the browser, under one playful identity, with every number on screen computed for real.

## Phases
Each phase is one or more branches and PRs into `main`; `main` stays deployable at every merge (the old app is kept at `/legacy/` until Phase 2 replaces its content). Phases 1 and K run in parallel with 0 where files do not overlap.

### Phase 0 — Foundation (shell, identity, engine)
- `tokens.css` and identity: dark canvas, per-lab hue spectrum, self-hosted display face + JetBrains Mono, the ten-dot mark, light theme.
- App shell: landing page (the ladder as a vertical climb, each rung a live thumbnail), lab router with code-splitting, shared chrome, About with lineage credits.
- Engine: `useScene` hook around Three.js r186 `WebGPURenderer` with WebGL fallback, DPR cap, visibility pause, frame-time probe, no-WebGL fallback slot.
- Systems: tour runner (ADR 0006), maths drawer, "toy weights" badge, reduced-motion handling, keyboard map.
- Checks: Vitest; Playwright smoke per lab (loads, no console errors, frame time recorded); axe light/dark at 390/1280; bundle budget (landing ≤ 250 KB gz, each lab ≤ 400 KB gz excluding model files); CI workflow.
- Docs: this tree, TRACKER, CHANGELOG, CLAUDE.md.
Accept when: landing + one placeholder lab render on WebGPU and WebGL; checks green; identity screenshots at 390/820/1280 in both themes approved by the owner.

### Phase K — Kernels (pure maths, in parallel with Phase 0)
- `labs/line/math.ts`: closed-form OLS, gradient descent with trace, MSE surface sampler.
- `labs/boundary/math.ts`: logistic regression with GD, perceptron rule, decision function sampler.
- `labs/net/math.ts`: MLP forward/backward (tanh/relu/sigmoid), SGD with mini-batch, datasets (spiral, moons, circles, xor), decision-surface sampler; structure may follow TF Playground's `nn.ts` under its Apache header.
- `labs/memory/math.ts`: tiny RNN and LSTM cells with a trained-offline weight set for a char task; forward trace exposing gates.
- Fixtures generated by `scripts/fixtures.py` (NumPy) and checked in; tests compare at 1e-6.
Accept when: all kernels pass fixture tests; each exposes a `trace()` the scenes can animate.

### Phase 1 — Fitting labs (Line, Boundary, Net)
- Line: scatter with draggable points; line updates live; mode switch closed-form vs GD with LR slider; 3D MSE bowl with the ball rolling along the GD trace; tour (5 steps).
- Boundary: paint tool; sigmoid sheet in 3D; boundary line on the floor; perceptron mode shows the update rule firing; tour.
- Net: paint tool + presets; layer/neuron controls; 3D decision terrain morphing per step; node graph with live weights (thickness, colour, dead-weight convention); loss sparkline; tour.
Accept when: 60 fps on M1 Air, ≥ 30 fps on a 2023 mid-range Android; frame probe recorded; axe 0; tours pass fixture tests; owner plays each and signs off on feel.

### Phase 2 — Attention labs (Attention, Block)
- Port `lib/transformer.ts` unchanged (19 tests stay green); new scenes: token ring with attention arcs per head, causal curtain, click-a-token; 3D block stack with the residual stream, step through, next-token bars; toy-weights badge on.
- Retire `/legacy/`.
Accept when: same as Phase 1; the old tests still pass.

### Phase 3 — Representation labs (Space, Sight, Memory)
- Space: pick and license a small embedding set (≈ 5k words, 50d), PCA to 3D in TS, point cloud with search, nearest neighbours, analogy arrows.
- Sight: train a tiny CNN (MNIST or a 10-class subset) with a documented script, export ONNX, run with onnxruntime-web; canvas to draw; filter sweep animation; activation stack in 3D; prediction bars.
- Memory: scenes on the Phase K kernels: the loop, the cell, the gates.
Accept when: model READMEs record source, script, licence and accuracy; same perf and a11y gates.

### Phase 4 — Frontier (Noise, Frontier)
- Noise: tiny diffusion (train on a small image set, export) or a precomputed trace with the badge; timeline scrub; noise-prediction vector field.
- Frontier live: `@huggingface/transformers` 4.x on WebGPU; Qwen3-0.6B q4f16 instrumented (Q/K/V outputs) via `models/frontier/instrument.py`; validator in CI on toy inputs; opt-in download with size; SmolLM2-360M fallback; 28×16 attention wall lighting up per generated token; `<think>` segments rendered as thinking.
- Frontier static: DeepSeek-V3 to scale from `config_671B.json` (MLA squeeze 7168→512, 256 experts / 8 active / group-limited); every number cited.
Accept when: generation works on a laptop with WebGPU and degrades honestly without it; validator green; numbers cited.

### Phase 5 — Polish and launch
- Landing thumbnails are live mini-scenes; OG images per lab; hub case page and OG refreshed (ADR 0004); README rewrite; post-launch audit with Lighthouse and frame probes on real devices.

## Sequencing
0 and K this week → 1 and 2 next → 3 → 4 → 5. Phases 1–4 each ship behind the landing page as they merge; a lab not yet built shows as "coming" on the ladder.

## Risks
- 3D performance on phones → DPR cap, instancing, per-lab no-WebGL fallback, measure early on a real Android.
- Model downloads (Qwen3-0.6B ≈ 1.4 GB VRAM) → opt-in, size shown, SmolLM2 fallback, cache in the Cache API.
- Accuracy drift between caption and scene → captions read values from the same state the scene renders.
- Scope → the ladder is the whole list; anything else goes to TRACKER "Later".
